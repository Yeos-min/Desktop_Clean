# 정리대 — Desktop Cleanup 프로토타입

내 바탕화면을 "정리해야 할 물건이 흩어진 공간"으로 바꾸고, 손으로 집어 폴더에 넣으며 정리하는 웹 프로토타입.
기본 화면은 Three.js 3D 장면이다. `?view=2d`로 0-C 때의 2D 보드와 나란히 비교할 수 있다 (같은 인터페이스, 같은 좌표계).

두 가지 모드가 있다.

| | 웹에서 바로 체험하기 | 내 Desktop과 연결하기 |
|---|---|---|
| 설치 | 없음 | Desktop Helper 실행 (Node 20+, 설치 없음) |
| 데이터 | 진짜 내 바탕화면 (Ctrl+A 드롭) | 진짜 내 바탕화면 (자동 스캔) |
| 이동 | 가상. 디스크 무변경. 결과는 "정리 계획" | 실제 rename. 탐색기에 즉시 반영. 되돌리기도 실제 |
| 확인창 | 0 | Chrome의 로컬 네트워크 접근 1번 (실기기 확인 전) |
| 코드 | `WebDropProvider` | `NativeHelperProvider` + `helper/desktop-helper.mjs` |

> 자동 테스트 통과는 실제 Windows 바탕화면에서 동작한다는 근거가 아닙니다. 실기기 확인 항목은 CLAUDE.md §3에 있습니다.

## 실행

```bash
npm run dev
```

- 웹 체험: `http://localhost:5173/` → 바탕화면에서 Ctrl+A → 드롭 → 책상 열기
- 샘플(디스크 무변경, 개발용): `http://localhost:5173/?storage=memory` (`&delay=0`으로 지연 끄기)
- Helper 연결(개발): 다른 창에서 아래를 실행하면 연결 주소가 나온다. **`--desktop`은 반드시 더미 폴더로.**

```bash
node helper/desktop-helper.mjs --dev --app http://localhost:5173 --desktop "C:\Users\me\Desktop\_test"
```

```bash
npm test
```

개발용 URL 파라미터: `capacity=16` 보드 정원, `refill=6` 파동 임계, `seed=123` 배치 시드, `view=2d` 2D 보드로 비교.

## 3D와 모델 교체

### Cozy room 시각 프로토타입 (2026-09-18)

- 기본 1인칭에 크림색 벽, 나무 바닥, 침대·창문·책상·식물과 벽면 수납장을 추가했다.
- `js/three/cozy-room.js`는 코드로 만든 장식물이며 파일 처리와 분리되어 있다. 완성형 GLB 모델을 사용한 장면은 아니다.
- 실제 목적지 상자는 기본 `벽면 수납장` 배치에서 수납장 칸에 들어간다. 상자에 파일 넣기·하위 폴더 열기는 기존 세션 동작을 사용한다.
- 손에 든 카드는 시점 오른쪽에 보인다. 여러 장은 최대 5장을 겹쳐 보여주고 전체 선택 수는 HUD에 표시한다.
- 우측 상단 톱니바퀴에서 배치·카메라·새 폴더·기록을 연다. `Tab`은 파일 정리 / 상자 배치 모드를 전환한다.
- 웹 체험의 디스크 무변경 정책과 Helper 코드는 변경하지 않았다.

three.js r185는 `vendor/three/`에 넣어 두었다. CDN을 타지 않으므로 발표 중 네트워크가 끊겨도 돌아간다.

- **모델을 넣으려면** `models/`에 `.glb`를 두고 [`js/three/assets.js`](js/three/assets.js)의 경로만 채운다. 규격은 [`models/README.md`](models/README.md).
  지금은 전부 프리미티브(둥근 카드, 나무 상자)다. 파일이 없거나 깨져도 프리미티브로 되돌아가고 장면은 죽지 않는다.
- **손맛을 만지려면** [`js/three/tuning.js`](js/three/tuning.js) 한 파일만 보면 된다. 카메라 각도, 스프링 세기, 더미가 따라오는 지연, 상자가 뜨는 높이가 전부 거기 있다.
  브라우저 콘솔에서 `__tuning.card.spring.freq = 6` 처럼 즉시 바꿔 볼 수 있다.
- 콘솔 손잡이: `__app.store`(세션 상태), `__board`(장면), `__tuning`(수치). `__board.snap()`은 애니메이션을 건너뛰고 제자리에 붙인다.

## 조작 (1인칭)

기본 화면은 1인칭이다. 방 안에 서 있고, 파일이 바닥에 깔려 있으며, 폴더 상자가 앞쪽에 놓여 있다.

| | |
|---|---|
첫 클릭으로 마우스를 잡으면(포인터 락) 화면 가운데 조준선이 생기고 마우스가 곧 시점이 된다. <kbd>Esc</kbd>로 언제든 마우스를 놓는다.

| | |
|---|---|
| 마우스 | 둘러보기 |
| <kbd>W</kbd><kbd>A</kbd><kbd>S</kbd><kbd>D</kbd> / 화살표 | 걷기. <kbd>Shift</kbd>로 빠르게 |
| 카드를 보고 클릭 | 한 장 집어 손에 든다 |
| 누른 채 훑기 | 조준선에 닿는 대로 손에 담긴다 |
| 폴더를 보고 클릭 | 들고 있던 걸 전부 넣는다. 빈손이면 폴더가 열린다 |
| 폴더를 잠깐 겨누고 있기 | 안의 칸이 열린다 (스프링 폴더) |
| 빈 바닥을 클릭 | 들고 있던 걸 거기에 내려놓는다 |
| 오른쪽 버튼 | 겨누는 자리에 그대로 내려놓는다 |
| 더미를 보고 클릭 | 다음 무더기를 꺼낸다 |
| <kbd>1</kbd>~<kbd>9</kbd> | 들고 있는 걸 보이는 줄의 N번 폴더에 넣기 |
| <kbd>Ctrl</kbd><kbd>Z</kbd> | 마지막 더미 되돌리기 |
| <kbd>Tab</kbd> | 파일 정리 / 상자 배치 모드 전환 |
| <kbd>Esc</kbd> | 마우스 놓기 |

카메라 선택칸에서 `사선` / `낮은 사선` / `탑다운`으로 바꿔 비교할 수 있다. 0-C 때 검증한 고정 사선이 그대로 남아 있다.

## 사용 흐름

1. 파일은 카드로 책상에 흩어지고(군집별로 느슨하게), 폴더는 배송지 상자가 된다. 보드에는 16장씩 올라오고 나머지는 더미에서 이어서 나온다.
2. 카드를 보고 클릭해 손에 담고(누른 채 훑으면 여러 장), 상자를 보고 클릭하거나 숫자 키 `1`~`9`로 N번에 넣는다. 한 번에 넣은 더미는 한 배치다.
3. 상자 위에 더미를 잠깐 올려 두거나 상자를 클릭하면 안의 칸(하위 폴더)이 한 단계 열린다. 첫 칸 `← 이름`은 그 폴더 자체이고, 칸에 넣으면 줄은 상자 목록으로 돌아온다. `Esc`로도 닫힌다.
4. 동명 파일이 있으면 그 카드만 튕겨 돌아온다. 덮어쓰지 않는다.
5. `새 폴더`로 상자를 만들 수 있다. Helper 모드는 실제 폴더, 체험 모드는 가상 폴더.
6. `Ctrl+Z`는 마지막 더미를 되돌린다. Helper 모드는 rename 역방향이라 탐색기에도 반영된다.
7. 오른쪽 "정리 계획/결과"에 폴더별로 무엇을 옮겼는지 남는다.

## 안전장치

- 덮어쓰기 없음. 자동 이름 변경도 없음. 검사와 이동이 **한 동작**이라 그 사이에 생긴 파일도 덮어쓰지 않는다.
- 되돌리기는 경로만 보지 않는다. 옮길 때 적어 둔 파일의 정체와 대조해, 밖에서 그 자리에 놓인 다른 파일은 건드리지 않는다.
- 삭제 없음. Helper에 삭제 API 자체가 없다.
- Helper는 바탕화면 밖을 다루지 않는다. 경로는 realpath 후 검사하고, 바로가기·정션은 거부한다.
- 웹은 절대경로를 모른다. id로만 말한다.
- 다른 드라이브로는 옮기지 않는다 (rename이 원자적이지 않으므로).
- 웹 체험 모드는 File System Access API의 쓰기 함수를 부르지 않는다.
- 테스트는 반드시 더미 폴더에서. Helper는 `--desktop`으로 가짜 바탕화면을 지정할 수 있다.

## 샘플 상자 내부 탐색 추가 (2026-09-19)

`?storage=memory`에서 샘플 바탕화면을 시작한다. 빈손으로 상자를 클릭하면
탑다운 카드 트레이 형태의 내부 화면이 열린다. HTML/CSS 기반 2.5D 표현이며,
별도 Three.js 내부 공간/카메라를 만든 것은 아니다.

- 파일 클릭: 하나 선택. Shift+클릭: 선택 추가/해제.
- Esc 또는 ‘들고 돌아가기’: 선택한 파일을 꺼내 손에 든 채 방으로 돌아오기.
- 다른 상자 클릭: 넣기. 우클릭: 바닥에 놓기. Ctrl+Z: 넣기와 꺼내기를 역순으로 되돌리기.
- 하위 폴더 클릭 / 상위 폴더 버튼: 한 단계씩 탐색. 폴더를 바꾸면 내부 선택은 해제된다.
- ‘이 폴더를 목적지로 펼치기’: 기존 배송지 탐색처럼 현재 폴더와 하위 폴더 상자들을 방에 표시.
- 원래 상자 안에 있던 샘플 파일은 열람만으로 진행률에 추가하지 않는다. 꺼내면 정리 대상에 추가된다.
- 실제 파일과 Helper는 기존 동작 그대로다. 이 내부 탐색/꺼내기는 MemoryProvider에만 연결했다.

검증: 자동 테스트 64개 통과(새 테스트 5개 포함). 내장 브라우저의 커서 대체 조작으로
내부 탐색, 빈 폴더, Shift 다중 선택, Esc 복귀, 다른 상자에 넣기, 우클릭 내려놓기,
연속 Ctrl+Z를 확인했다. 일반 Chrome의 포인터 락 조작과 실제 파일 시스템 검증은 하지 않았다.

## 상자 배치 모드 (2026-09-19)

- 기본 벽면 수납장 배치로 시작한다. Tab 또는 우측 상단 모드 버튼으로 전환한다.
- 배치 모드: 좌클릭으로 상자를 집고, 바닥 또는 빈 수납칸을 겨눈 뒤 다시 좌클릭해서 놓는다.
- 반투명 초록색은 배치 가능, 빨간색은 불가능이다. 벽·침대·책상·의자·화분·수납장·다른 상자와의 겹침을 검사한다.
- 우클릭, Esc, 모드 전환은 미확정 배치를 취소한다. 확정 전 원래 위치를 변경하지 않는다.
- 배치 모드의 Ctrl+Z/되돌리기 버튼은 상자 위치 이력만, 파일 모드에서는 기존 파일 이동 이력만 되돌린다.
- 위치는 폴더 ID에 연결된 세션 메모리에 저장된다. 상자의 연결 폴더와 내부 파일은 바꾸지 않고, 파일 Provider를 호출하지 않는다. 새로고침하면 기본 위치로 돌아간다.
- 상자를 든 상태에서 휠로 15°씩 양방향 회전한다. 내려놓은 방향도 세션에 유지하고, 취소/Undo는 위치와 방향을 함께 복구한다.
- 바닥 배치와 기존 수납칸 복귀를 지원한다. 상자 쌓기는 지원하지 않는다. 회전한 상자의 바닥 면적을 기준으로 충돌을 검사하며, 수납칸보다 커진 방향은 놓을 수 없다. 가구는 보수적인 직사각형 영역으로 검사한다. 많은 폴더의 기본 배치 개선은 별도 후속 작업이다.

검증: 자동 테스트 69개 통과(배치 관련 5개 추가). 내장 브라우저의 커서 대체 조작으로
Tab 전환, 상자 집기/바닥에 놓기, 다른 상자와 겹침 차단, 우클릭 취소,
배치 Undo, 옮긴 상자에서 기존 폴더 내용 열기를 확인했다. 오류 로그는 없었다.
일반 Chrome의 포인터 락 조작은 별도 검증하지 않았다.

휠 회전 검증 (2026-09-20): 자동 테스트 74개 통과(회전 관련 5개 추가).
내장 브라우저의 커서 대체 조작으로 양방향 휠 회전, 확정 후 다시 집었을 때 방향 유지,
회전 취소, Undo로 원래 위치와 방향 복구, 회전한 상자의 내부 탐색을 확인했다.
오류 로그는 없었다. 일반 Chrome의 포인터 락과 실제 마우스 휠 감도는 별도 검증하지 않았다.

## 범위 밖

- 바탕화면 루트를 통째로 권한 요청하는 것 (Chromium이 막는다), 우회 시도
- 재귀 스캔·재귀 복사. 폴더는 한 단계씩만
- 삭제. 필요해져도 휴지통 이동이 먼저
